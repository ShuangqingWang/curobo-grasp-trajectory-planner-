# 轨迹规划逻辑分析 — 碰撞空间范围与 ESDF 方案

> 本文定义两件事：
>
> 1. **碰撞空间范围**：点云如何截断、长方体六个方向如何确定；
> 2. **ESDF 建立**：长方体内如何由点云与工作台建立有符号距离场。
>
> 距离场只在该长方体内建立，**长方体之外一律视为不碰撞**。
>
> 单位：长度 mm。所有坐标均为**基座坐标系**。

---

## 1. 坐标系与工作台

以基座坐标系为原点，长方体按 **+X、−X、+Y、−Y、+Z、−Z** 六个方向分别确定。

机器人基座安装在工作台上，**基座坐标系的 XOY 平面就是工作台顶面**。

| 项                               | 值                           | 来源                                                                                 |
| -------------------------------- | ---------------------------- | ------------------------------------------------------------------------------------ |
| 工作台顶面                       | z = 0                        | `config/base/app.json` → `base_platform.positive_extent_xyz_mm[2]` = 0.0        |
| 工作台高度                       | 1000                         | `config/base/app.json` → `base_platform.negative_extent_xyz_mm[2]` = 1000.0     |
| **工作台底面（−Z 下界）** | **z = −1000**         | 上一项取负                                                                           |
| 工作台 XY 范围                   | X[−400, 400]　Y[−400, 400] | `base_platform.negative_extent_xyz_mm[0,1]`、`positive_extent_xyz_mm[0,1]` = 400 |

> 佐证：基座外壳网格 `base_link.STL` 的 z 范围为 [0, 61.8]，基座底面正好落在 z = 0。

**工作台是固定障碍：不参与长方体范围的确定，但落在长方体内的部分写入距离场作为障碍。**

> 写入工作台**不增加显存**：距离场是稠密网格，长方体内每一格都存一个距离值，
> 与该格是否为障碍无关。显存只由长方体的格子总数决定。

## 4. 计算步骤

### 第一步：截断点云

**点云必须先截断，截断后剩下的点才参与长方体范围的确定。**

```text
z_hi = max(拍照法兰.z, 放置法兰.z)

保留点 p，当且仅当：
    |p.x| ≤ CAP
    |p.y| ≤ CAP
    −1000 ≤ p.z ≤ z_hi
```

### 第二步：确定长方体

```text
+X：x_hi = max(截断后点云.x_max, 拍照法兰.x, 放置法兰.x)
−X：x_lo = min(截断后点云.x_min, 拍照法兰.x, 放置法兰.x)
+Y：y_hi = max(截断后点云.y_max, 拍照法兰.y, 放置法兰.y)
−Y：y_lo = min(截断后点云.y_min, 拍照法兰.y, 放置法兰.y)
+Z：z_hi = max(拍照法兰.z, 放置法兰.z)
−Z：z_lo = max(−1000, 截断后点云.z_min)
```

−Z 的含义：截断后点云的最低点若高于工作台底面，下界取点云最低点；
若有点低于工作台底面（已在第一步切掉），下界取工作台底面 −1000。

**不外扩。**

### 第三步：体素化

```text
网格尺寸  n_i = ceil((hi_i − lo_i) / 体素边长)
网格原点  origin = 长方体中心 − (n − 1) / 2 × 体素边长      （0 号格的中心）

点云：   index = rint((p − origin) / 体素边长)，所在格置为障碍
工作台： 与长方体相交的部分整块置为障碍
```

`rint` 为"四舍六入五成双"。结果是一个与长方体同尺寸的**占据栅格**（每格一个布尔值）。

### 第四步：建立 ESDF

详见第 5 节。

## 5. ESDF 建立

### 5.1 ESDF 是什么

**E**uclidean **S**igned **D**istance **F**ield，欧氏有符号距离场：
长方体内每一格存一个数，表示**该格到最近障碍表面的直线距离**。

| 位置     | 值                     |
| -------- | ---------------------- |
| 障碍外   | **正**，越远越大 |
| 障碍表面 | 0                      |
| 障碍内   | **负**，越深越负 |

> ⚠ **符号约定不能反**：必须"障碍外为正、障碍内为负"。
> 反过来会让整个世界被当成实心，任何构型都判为碰撞。

碰撞检测时，半径 r、球心 c 的碰撞球：

```text
穿透量 = r + 激活距离 − d(c)
穿透量 > 0  →  判定碰撞
```

`d(c)` 由规划器对相邻 8 格做**三线性插值**得到，并同时得到解析梯度。

### 5.2 算法

由占据栅格计算精确的欧氏距离变换（EDT），在 GPU 上完成，**分两遍**：

```text
第一遍（外部距离）：以"障碍格"为站点 → 每格到最近障碍格的距离，记为正
第二遍（内部深度）：以"自由格"为站点 → 障碍格到最近自由格的距离，取负
合成：障碍格取第二遍的负值，其余格取第一遍的正值
```

每一遍的核心是**并行带状算法（Parallel Banding Algorithm，PBA）**：

| 项   | 内容                                                                                      |
| ---- | ----------------------------------------------------------------------------------------- |
| 结果 | **精确**欧氏距离，非近似                                                            |
| 执行 | GPU 上 5 次 kernel：FloodZ → MaurerAxis → ColorAxis → MaurerAxis → ColorAxis          |
| 输入 | 站点数组：每格存"自身坐标"（是站点）或 −1（非站点）                                      |
| 输出 | 同一数组被原地改写为"该格最近站点的坐标"                                                  |
| 实现 | cuRobo 自带`curobo._src.perception.mapper.esdf.edt_parallel_banding.ParallelBandingEDT` |

站点坐标按每轴 10 bit 打包进一个 int32：

```text
| 2 位未用 | 10 位 Z | 10 位 Y | 10 位 X |
```

> ⚠ **单轴格数上限 1024**。超限必须**显式报错**，不得静默算错。

PBA 给出的是"最近站点坐标"，距离由它换算：

```text
d = √((x − sx)² + (y − sy)² + (z − sz)²) × 体素边长
```

### 5.3 计算方式

**① 站点数组与 PBA 缓冲两遍共用。**
第一遍结束、距离写出后，同一块站点数组重新播种为第二遍的站点，
PBA 对象（含其内部缓冲）只创建一次。

**② 播种与求距离按块进行。**
沿 X 方向每次处理约 200 万格：

```text
对每一块：
    播种：   块内格子 → 是站点则写入打包坐标，否则写 −1
    求距离： 解码块内最近站点坐标 → 整数算平方和 → 开方 × 体素边长 → 写入输出
```

- 本格坐标用三个一维序列靠广播参与运算，**不展开成整网格**
- 坐标差与平方和在 int32 中计算（最大 3 × 1024² 不溢出），最后才转浮点
- 结果**直接写成 fp16**，即交给规划器的最终格式

**③ 边界情况**：长方体内无任何障碍 → 全部填 +10 m；全部为障碍 → 全部填 −10 m。

### 5.4 显存

整个建立过程中只有四块与网格同尺寸的数组：

| 数组              |      字节/格 | 用途                   |
| ----------------- | -----------: | ---------------------- |
| 占据标记          |            1 | 两遍都用它区分内外     |
| 站点数组          |            4 | PBA 原地改写，两遍共用 |
| PBA 缓冲          |            4 | 算法内部需要，两遍共用 |
| ESDF 输出（fp16） |            2 | 最终结果               |
| **合计**    | **11** |                        |

其余中间量只在块内临时存在（约 200 万格 × 数个 int32，量级几十 MB）。

建立完成后，**常驻的只有 fp16 输出，2 字节/格**。

站点数组与 PBA 缓冲是该算法本身所需，11 字节/格即其下限。

### 5.5 实测

条件：第 6 节样本输入，工作台写入，RTX 4060。

| 网格格数 | 建立耗时 | 峰值显存 | 常驻显存（fp16） |
| -------: | -------: | -------: | ---------------: |
|    6.1 M |   9.6 ms |   111 MB |            12 MB |
|   11.9 M |  17.3 ms |   172 MB |            23 MB |
|   28.1 M |  44.6 ms |   342 MB |            54 MB |
|   48.5 M |  78.6 ms |   553 MB |            92 MB |

峰值约 **11.4 字节/格**，与 5.4 的账一致；耗时约 **1.6 ms / 百万格**。

### 5.6 正确性

与 CPU 精确欧氏距离变换（`scipy.ndimage.distance_transform_edt`）**逐格零差异**：
fp32 结果最大差 0，转 fp16 后 0 格不一致。

## 7. 已知限制

**+Z 取法兰高度，不覆盖肘部。**
`z_hi` 取拍照、放置法兰的最大 z。运动中肘部可高于法兰，肘部上方若有障碍（支架、相机架等）
会在第一步被截掉。本轮点云最高 384，仅切掉 105 点。
